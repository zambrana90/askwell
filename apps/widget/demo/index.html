Widget demo

This page stands in for a customer's site. The chat button should appear in a corner.

Try it

  1. Edit the snippet at the bottom of this file: set src to your app URL + /widget.js (for example http://localhost:3000/widget.js) and data-key to a dev pk_… key.
  2. Serve this folder from a different origin than the app: python3 -m http.server 8080 (run it in apps/widget/demo), then open http://localhost:8080.
  3. Click the button. The panel opens; send a message and you get a mock reply. Close it with the ✕ or Escape.

Which app to point at

Easiest: the app running locally (pnpm dev, then http://localhost:3000). This page is on another origin than the app, which is the point of the demo.

A protected Vercel preview

Deployment Protection needs authentication on every request, and the widget's config fetch sends no cookies. So a bypass cookie (even samesitenone) is not enough: the fetch fails and nothing renders. Use a browser that adds the header x-vercel-protection-bypass: <secret> to requests for the preview host at the network level, for example Playwright: 

await context.route("https://YOUR-PREVIEW.vercel.app/**", (route) =>
  route.continue({ headers: { ...route.request().headers(), "x-vercel-protection-bypass": process.env.VERCEL_AUTOMATION_BYPASS_SECRET } }));

Added this way, the header does not trigger a CORS preflight. Do not use extraHTTPHeaders for it: that sends the header to every host (such as Clerk's) and their CORS checks reject it. Read the secret from the environment; never write it into this file or commit it.

The snippet

<script src="https://YOUR-APP.vercel.app/widget.js" data-key="pk_YOUR_KEY" async></script>
